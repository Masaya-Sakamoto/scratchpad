# 2.1 CNI/CSI選定

## 1. ネットワーク（CNI）選定

### Calico
- **メリット**: 高性能、成熟的、Kubernetesコミュニティで広く使用
- **特徴**: 
  - BGPベースのルーティング
  - ネットワークポリシー（L3-L7）
  - WAF（Web Application Firewall）機能
- **使用ケース**: 高性能ネットワークが必要な環境
- **推奨構成**: 3ノード以上、BGP peering設定

### Cilium
- **メリット**: eBPFベース、高パフォーマンス、可視化機能
- **特徴**: 
  - eBPFによるネットワーク機能
  - サービスメッシュ機能（Istio代替）
  - 高度な可視化
- **使用ケース**: 高度なネットワーク制御が必要
- **推奨構成**: Kernel 5.x以上、eBPFサポート

### Flannel
- **メリット**: 軽量、シンプル
- **特徴**: 
  - 基本的なIPv4/IPv6サポート
  - 設定が簡単
- **使用ケース**: 小規模クラスタ、テスト環境
- **推奨構成**: 小規模（10ノード以下）

### 推奨: Calico
- **理由**: 性能、機能、サポートのバランス
- **設定**: 
  - IPv4/IPv6デュアルスタック
  - ネットワークポリシー有効化
  - メトリクス収集

## 2. ストレージ（CSI）選定

### Longhorn
- **メリット**: Kubernetesネイティブ、高可用性
- **特徴**: 
  - 分散ブロックストレージ
  - 自動レプリケーション
  - スナップショット/クローン
- **使用ケース**: 状態fulアプリケーション、データベース
- **推奨構成**: 3-5ノード、3レプリカ

### Ceph
- **メリット**: 大規模、多機能
- **特徴**: 
  - ブロック、ファイル、オブジェクト
  - 自動レプリケーション
  - 自己修復
- **使用ケース**: 大規模クラスタ、多様なストレージ要件
- **推奨構成**: 5-7ノード、分散配置

### Portworx
- **メリット**: 企業向け、多機能
- **特徴**: 
  - 高性能
  - 高度なセキュリティ
  - 多様なクラウド対応
- **使用ケース**: エンタープライズ環境
- **推奨構成**: 3-5ノード

### MinIO（オブジェクトストレージ）
- **メリット**: S3互換、高性能
- **特徴**: 
  - オブジェクトストレージ
  - 分散配置
  - 自己ホスト
- **使用ケース**: データレイク、科学データセット
- **推奨構成**: 4-8ノード、100TB以上

### 推奨構成: Longhorn + MinIO
- **理由**: 
  - Longhorn: ブロックストレージ（状態fulアプリ）
  - MinIO: オブジェクトストレージ（データレイク）
- **設定**: 
  - Longhorn: 3ノード、3レプリカ
  - MinIO: 4ノード、分散配置

## 3. メトリクス収集

### Prometheus
- **機能**: 時系列データベース、クエリエンジン
- **コンポーネント**: 
  - Prometheusサーバー
  - Exporters（Node、cAdvisor）
  - Alertmanager（通知）
- **ストレージ**: 長期保存（LTS）
- **監視**: 
  - クラスタリソース使用率
  - ポッドメトリクス
  - サービスヘルス

### Grafana
- **機能**: 可視化、ダッシュボード
- **ダッシュボード**: 
  - クラスタ全体
  - ノード別
  - アプリケーション別
- **アラート**: Alertmanager連携

### Loki（軽量ログ）
- **機能**: ログ集約、検索
- **特徴**: 
  - Prometheus同様、ラベルベース
  - 軽量、低オーバーヘッド
- **代替**: EFKスタック（重いが機能豊富）

## 4. 自動スケーリング

### Cluster Autoscaler
- **機能**: ノードの自動増減
- **トリガー**: 
  - 未スケジュールのポッド
  - リソース使用率
- **設定**: 
  - 最小/最大ノード数
  - 拡張/縮小ポリシー

### KEDA（イベント駆動スケーリング）
- **機能**: イベントベースのスケーリング
- **トリガー**: 
  - メッセージキュー
  - 外部API
  - カスタムメトリクス
- **使用ケース**: 非連続的なワークロード

### VPA（Vertical Pod Autoscaler）
- **機能**: リクエスト/制限の自動調整
- **設定**: 
  - 推奨値の提案
  - 自動適用
- **注意**: ポッド再起動が必要

## 5. セキュリティ

### 認証/認可
- **RBAC**: 権限ベースのアクセス制御
- **Service Account**: ポッドの認証
- **外部認証**: LDAP/Active Directory連携

### ネットワークセキュリティ
- **ネットワークポリシー**: トラフィック制御
- **mTLS**: サービス間通信暗号化
- **WAF**: Webアプリケーション保護

### 監査
- **Audit Log**: 全操作ログ
- **保持期間**: 90日以上
- **分析**: 異常検知

## 6. 導入ステップ

1. **基盤ネットワーク設定**（1週間）
   - CNI選定・インストール
   - ネットワークポリシー設定
   - 接続性テスト

2. **ストレージ設定**（1週間）
   - CSIインストール
   - ストレージクラス作成
   - 永続ボリューム作成

3. **監視基盤構築**（1週間）
   - Prometheus/Grafanaセットアップ
   - ダッシュボード作成
   - アラート設定

4. **自動スケーリング**（1週間）
   - Cluster Autoscaler設定
   - KEDA設定（必要に応じて）
   - テスト実行

5. **セキュリティ強化**（1週間）
   - RBAC設定
   - ネットワークポリシー適用
   - 監査ログ設定
